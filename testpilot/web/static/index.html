EVIDENCE-GROUNDED REGRESSION TESTING RESEARCH

TestPilot — Evidence-Grounded AI for Change-Aware Regression Testing

Repository Evolution → Specification-Grounded Testing → Three-Valued Failure Arbitration

TestPilot combines deterministic repository analysis with LLM-based reasoning to identify regression tests affected by code changes, generate specification-grounded boundary tests, and classify failures as code defects, invalid test assertions, or specification ambiguity.

1. Repository-Aware Regression Analysis

Identifies changed symbols and affected regression tests using Git, AST/Tree-sitter, qualified symbol identity, and repository-level code intelligence.

2. Specification-Grounded Testing

Extracts deterministic boundaries from OpenAPI specifications and combines them with repository context for boundary-oriented test generation.

3. Three-Valued Failure Arbitration

Classifies failures into TRUE_CODE_DEFECT, INVALID_TEST_ASSERTION, or SPEC_AMBIGUITY_OR_DEFECT using code, test, and specification evidence.

    Evaluation Methodology & Metric Definitions

    Precision TP / (TP + FP)

    Measures how many selected tests are actually relevant to the changed symbols. High precision means minimal developer waste from running irrelevant tests.

    Recall TP / (TP + FN)

    Measures how many relevant ground-truth tests were successfully selected. High recall ensures safety against missed regressions.

    F1-Score 2·P·R / (P + R)

    Harmonic mean balancing precision and recall, ensuring neither over-selection nor unsafe under-selection dominates the score.

    Test Reduction 1 - (Sel / Total)

    Percentage of the full regression test suite safely skipped. Quantifies CI/CD execution time and resource savings.

    Pallets Flask: Pytest Fixture Injection & Recall Loss

    pallets/flask (375 tests | 5 Ground Truth)

    In Pallets Flask commit de8429ff → 7203feab, Flask.run was modified. Tests invoke app.run() where app is dynamically injected across module boundaries by pytest fixtures without static type annotations.

    Naive Name Matching 19 SELECTED (100% RECALL)
    Changed Symbol: run
    Matching Strategy: Bare token matching across test files
    Tests Selected: 19 tests (5 TP, 14 FP)
    Outcome: High recall (100%), but low precision (26.32%) due to 14 false-positive bare token matches.
    TestPilot Qualified Identity 0 SELECTED (0% RECALL)
    Qualified Symbol: Flask.run
    Matching Strategy: Receiver type inference on call sites
    Tests Selected: 0 tests (0 TP, 0 FP, 5 FN)
    Scientific Interpretation: "Qualified identity completely eliminated false positives, but missed dynamic pytest fixtures where the receiver type is not statically resolved across files, demonstrating an inherent trade-off of purely static AST reasoning."

    Handled Edge Cases & Uncertainty Mitigation

    Generic Verbs ('run', 'handle', 'dispatch')

    Enclosing class stacks and AST receiver type inference prevent matching generic verbs across independent subsystems.

    Negative Controls & Empty Ground Truth

    When expected ground truth is empty or 0/0, TestPilot reports 'N/A' rather than hallucinating 100% precision or recall.

    Unresolved External Dependencies

    Third-party library boundaries (e.g. Werkzeug) are tracked with explicit uncertainty scores and confidence degradation.
